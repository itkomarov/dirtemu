# RX 570 shader and geometry corrections, 28 November 2026

Author: carunodev

This work addresses demonstrated translation and pipeline failures. Normal
gameplay rendering and sustained five FPS still require an actual game test.

## FSR4 chain

Four actual shaders now translate, pass Microsoft DXIL validation and create
RX 570 compute pipelines. The complete four-shader check passes in SM 6.5;
SM 6.6 checks also established pipeline creation before the final equivalent
strict-add refinement to packed FP16 accumulation. Final preparation uses
the same release binary and shader configuration as the subsequent game.

| Shader | Role | Corrected failure |
|---|---|---|
| `fdce2a0a9fb1521a` | FSR4 postpass | wave32 operations in a 256-thread group |
| `47d8c225abfcb246` | neural pass5 | guarded row permutation and logical wave32 bit reductions |
| `6a6c7b7fde59134f` | prepass | immediate sampler recognition and packed FP16 multiply-accumulate |
| `ba578b59c8c28a57` | SPD auto-exposure | packed 16-bit coordinates for a 32-bit atomic and integer counter reset |

The wave32 fallback applies to compute shaders on devices whose minimum and
maximum physical wave sizes are both 64. It keeps the original logical
thread IDs, group dimensions and LDS addressing. Lane index, ballot,
read-first, read-lane and integer bit reductions operate independently in
each 32-lane half. Other wave operations remain refused. Half-dependent
descriptor indices are conservatively marked nonuniform.

Ballots use internal aggregate projections; the output contains no LLVM
`insertvalue`, which DXIL rejects. Whole aggregate consumers fail translation
before optimization and serialization. GPU tests cover independent halves,
partial active masks, groups 64/128/256 and a multidimensional group.

The packed multiply-accumulate reads both halves of the old destination.
Its rounding correction handles finite overflow and fused halfway cases
without requiring double precision. An independent fixed-point integer
oracle checks 549,120 GPU results per profile/configuration. The exact
product-plus-add path uses ordinary floating-point operations without LLVM
fast-math flags. Other legacy FP16 lowering paths are outside this correction.

The auto-exposure atomic uses A16 coordinates with D16 disabled: two unsigned
16-bit coordinates occupy a VGPR; its data and returned value are 32-bit.
The counter reset is accepted only when a matching static descriptor-table
entry has a demonstrated 32-bit image atomic. General partial-channel float
stores and D16 atomics remain unsupported. GPU tests verify integer bit
patterns, packed coordinates and returned old values.

## Geometry

Two real material pixel shaders previously declared 35 and 40 signature
rows. Software vertex aliases left unused original inputs behind. Removing
only unreferenced entries and compacting input IDs/rows lets both shaders
validate and create RX 570 graphics pipelines.

Only signature-ID operands of input calls are remapped. Shared arithmetic
constants, interpolation modes, component packing and dynamic vertex operands
are preserved. The geometry stage retains all source vertex inputs, emits
the requested outputs, and keeps mandatory raster outputs. A GPU test renders
two triangles and checks all six original vertices, dynamic vertex selection
and primitive IDs. Existing perspective, linear and rectangle tests pass.

## Sources and validation

The sampler constant folds and packed accumulator operand handling adapt
[avatarmanz 014d52d](https://github.com/avatarmanz/VIctory-7900XTX/tree/014d52dedf837d1ac660a0bd256c4704be9eeb40).
The guarded permutation and counter-store handling adapt
[NVIDIA 0cef07e9](https://github.com/trustno1-coder/VIctory-NVIDIA/tree/0cef07e9d766df48f0e95f13ce3bbbe2290fe9d3).
The logical half-wave lowering, aggregate escape checks, FP16 rounding and
signature compaction are local adaptations with numerical regressions.

Coordinate/data widths follow the
[AMD RDNA2 ISA](https://docs.amd.com/api/khub/documents/Et~wpu9g~Ffl7d9q0QZ~Og/content),
section 8.2. Inactive permutation behavior follows the
[AMD LLVM modifier documentation](https://rocm.docs.amd.com/projects/llvm-project/en/docs-7.1.1/LLVM/llvm/html/AMDGPUModifierSyntax.html#bound-ctrl).

The full GPU crate suite passes 242 tests with one existing ignored test.
Scoped shader checks cover both SM 6.5 and SM 6.6. Pipeline creation alone
does not prove that every binding and dependency is correct during gameplay.
The observed memory pressure, host-copy admission failures and previous
desktop-wide video-engine timeout still require runtime verification.
